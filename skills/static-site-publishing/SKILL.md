# Static site publishing

## When to Use

Building, previewing, or publishing one of Karl's static sites (project or brand domains on Cloudflare Pages).

## Always-on rules

- **Plain by default.** Hand-written HTML/CSS, generated by a short stdlib Python `build.py` when content comes from data files. No framework, bundler, or npm toolchain unless Karl asks; an existing site using a framework is not a reason for a new one to.
- **Private before public.** Every page carries `<meta name="robots" content="noindex">` until Karl approves publication; nothing goes to the public domain without his explicit yes.
- **Belief or position text is Karl's to write.** Draft from his own words and mark it clearly as a draft for him to rewrite.
- **Publish limits next to data.** Any results page states its method limits above the table, not on a separate page.
- Check data files for secrets before copying them into the site tree.
- **Measure before promoting.** Every public site carries Karl's umami tag before anything links to it; posting without analytics leaves channel results unknowable. Add-a-site recipe, ingestion check, and Cloudflare traffic access: `references/analytics.md`.

## Procedure

1. Scaffold `~/src/<site>/` with `build.py`, output `site/`, `git init`.
2. Build: `python3 build.py`. Escape all data with `html.escape(str(x))` (data values are not always strings), and normalise result fields that may be dicts, lists, or stringified dicts.
3. Private preview on the tailnet: serve `site/` with a user systemd unit running `python3 -m http.server <port> --bind 127.0.0.1 --directory <site>`, then `tailscale serve --bg --https=8443 http://127.0.0.1:<port>`. Proxy to localhost instead of serving the folder directly: Tailscale folder serving needs root. Verify each page with `curl -w '%{http_code}'` on the tailnet URL.
4. On approval: deploy `site/` to Cloudflare Pages, register the custom hostname on the Pages project, add DNS, drop `noindex`.
5. Commit after each build (`git add -A`, `.gitignore` with `__pycache__/`); `build.py` page helpers must take a `depth` arg so subdirectory pages (e.g. `articles/`) get correct `../` nav links.

## Putting a site on hold

To pause a live site, add a `holding/` folder and repoint the Pages build output to it through the API. Don't delete anything, and verify every hostname and path. Stale-cache pitfall and steps: `references/holding-page-and-takedown.md`.

## Moving content between sites

When moving posts from another site (e.g. the Astro site in `~/src/site`) into a plain site, follow `references/content-migration-and-cowriting.md`. Core rules: copy originals verbatim with a review banner, keep the source site untouched, prepare 301 redirects but deploy them only together with the new domain going live.

## Journal publishing (agentrecourse.org)

Approved registry entries only: research articles and opinion pieces. `journal.json` registry (slug, title, date, summary, source path; research entries add repo and cited commit; opinion entries carry `"type": "opinion"`) drives `journal.py`, a stdlib markdown renderer (headings, tables, lists, blockquotes, code, figures with captions, `<https://>` autolinks; strip HTML comments first). It copies figures per article, rewrites figure paths, and inserts a canonical link to `https://agentrecourse.org/<journal|opinion>/<slug>` by entry type. Opinion entries render to `opinion/<slug>.html` with a head note stating the piece is opinion and not pre-registered (no code/commit line), and the listing labels them **Opinion** so the journal's pre-registration promise stays scoped to research articles. The head note's second sentence defaults to the list-piece wording ("the forecasts are argument"); personal essays set an optional registry `"note"` field instead, since that default misdescribes them. `publish_journal.py` builds `public/` from approved registry entries ONLY; the `build.py` preview tree holds unreviewed drafts and is never deployed. Deploy: `T=$(cat ~/.secrets/CLOUDFLARE_ACCOUNT_TOKEN); ACC=$(curl -s -H "Authorization: Bearer $T" https://api.cloudflare.com/client/v4/accounts | python3 -c 'import json,sys;print(json.load(sys.stdin)["result"][0]["id"])'); CLOUDFLARE_API_TOKEN=$T CLOUDFLARE_ACCOUNT_ID=$ACC npx -y wrangler@4 pages deploy public --project-name agentrecourse --branch main --commit-dirty=true`. Deploy only through wrangler: a hand-rolled Pages Direct Upload manifest via the REST API serves a partial tree (root returns 200 while article subpaths and figure assets 404 or 500). After every deploy, curl the root, one article page and one figure asset before calling it live.

Updating an article: (1) push the source repo first and check the diff for references to private/local material (e.g. `cost-predictor-local`, log paths, gen ids); (2) set the registry `commit` to the pushed head and refresh `summary` if the headline changed; (3) `python3 publish_journal.py`; (4) grep the built HTML for the new version line, the commit hash, and any retracted phrase (only retraction notes may still contain it); (5) deploy; (6) `curl` the live URL and grep version + commit; (7) commit the site repo.

- Research-article byline: Karl is the accountable author; a Contributions line names the AI agent's role (study design, analysis code, drafting) under his direction. AI agents are never listed as authors on research articles: they cannot answer for the work later. Opinion pieces name the model co-author in the byline instead (see opinion-essays): the piece claims no reproducibility, so the disclosure does the work a Contributions line cannot.
- Styling: Wikipedia look (Karl finds it familiar and readable): sans body, serif headings with hairline rules, link blue `#0645ad`, boxed numbered Contents, superscript citations, white page on grey with thin side borders, plus mobile and dark-mode rules. Write original CSS in that idiom; do not copy MediaWiki's Vector or MonoBook files, which are GPL-2.0 (Wikimedia Codex is MIT but is UI components, not an article stylesheet). Scrollable tables and figure captions carrying key numbers stay.
- Renderer features for long articles (`journal.py`): the rendered `## Sources` block (`[n] url — title` lines from grounded-citations) is parsed out and emitted as a numbered `<ol class="references">` with `id="cite-n"`, linked title, host, and a `^` back-link; every inline `[n]` becomes `<sup class="ref"><a href="#cite-n">` with the title as hover text, first use carrying `id="ref-n"`. h2s get slug ids and a Contents box is inserted after the first two paragraphs (a box at the first h2 sits below a long preamble where nobody sees it). Each article head carries meta description, OpenGraph, Twitter card and one canonical link, built from the registry summary. After building, check in the HTML: no raw `[n]` left in the body, references contiguous 1..N, no `#cite-n` link without a target.
- Format: stay on markdown to HTML for web essays; LaTeX only for a venue that demands it or math-heavy papers. A PDF can be generated from the same markdown with pandoc when needed.
- Visual check: screenshot the built page with headless Chrome (`google-chrome --headless=new --no-sandbox --hide-scrollbars --window-size=1280,1600 --screenshot=out.png file:///…/page.html`, and a 420px width for mobile), then inspect the PNG.
- Traffic: the journal is tracked in self-hosted umami (tag in `publish_journal.py` page head; see references/analytics.md). Pre-umami or bot-level numbers come from Cloudflare GraphQL with a least-privilege token (Pages Write + Account Analytics Read + Zone Read; it cannot touch DNS, billing, registrar or tokens, so those changes go through the owner's dashboard or a temporary token): query `viewer.accounts(filter:{accountTag})` with a `zoneTag` filter (zone-scoped `viewer.zones` fails authz; the REST zone analytics API is sunset). `httpRequestsAdaptiveGroups` gives path/country/browser per day; `clientRefererHost` is not available on the free plan, so referrals only come from umami. Exclude `Curl` and SE traffic when estimating readers (mostly our own checks).
- Every article page states its code repo and the exact commit whose text it is, since the repo is the reproduction path. Opinion pages carry no repo/commit note.
- The renderer restarts ordered-list numbering per list and headings break lists, so globally numbered content (say 1-100 across ten sections) is written as `**N.**` paragraphs, not markdown ordered lists, or the rendered numbers reset per section.
- Verify a rendered page by counting elements in the served HTML (`grep -c '<li>'`, `<table>`, `<figure>`): markdown text extractions of rendered pages silently drop lists and fabricate missing sections. Trust the HTML, not the extraction.

## Co-writing articles with Karl

Karl writes well but has little typing energy. Default loop: ask 3-5 short questions, he answers in fragments or dictation, draft in his voice reusing his words and marking assistant-written sentences, he edits via short notes. Every co-written piece ends with an AI-assistance disclosure line. He hides paragraphs by wrapping them in comment markers — in markdown use `<!-- -->` (C-style `/* */` renders as visible text), and convert his syntax when applying his edits. Details in the same reference.
